# DepthBokeh 景深架构

> 对应代码：`4375efc`（2026-10-30「修改 4x 虚化不准确的问题」）。改了架构请同步改这份文档。
> README 讲「怎么用、为什么这样调」；这份只讲**现在的结构，以及每一步由谁说了算**。

---

整体架构

1. **取深度**：按变焦倍率选深度来源（LiDAR、双摄或 AI），裁切到当前画面，并按颜色补上没测到的洞。
2. **定对焦**：取点击位置附近深度的中位数，经过防抖处理，得到对焦面。
3. **算镜头**：按 ƒ 值和焦距，算出每个深度对应的虚化半径。离对焦面越远越糊，前后各有一段全清晰区。
4. **修边缘**：用人像分割，把人物边缘上测错的深度改成各自那一侧的深度。头发、眼镜跟人走，外面一圈跟背景走。
5. **定主体**：认出点中的那一个人或物体，把它整体拉到对焦面。再加上镜头本来就清晰、和对焦点连着的区域，用颜色把边缘补齐。
6. **渲染**：按每个像素最终的深度分层做圆盘模糊，清晰的地方贴回原图细节，输出画面。


-----



## 1. 原则

| 问题 | 谁说了算 |
|---|---|
| 一个像素糊多少 | **镜头**：只看它的视差和对焦面视差的差（`LensParameters.signedBlurRadius`），和它是不是人、是不是物体无关。同一距离的东西虚化一样 |
| 主体和背景的边界在哪 | **分割**（Vision）+ 颜色：修掉深度图在边缘上的错误深度 |
| 点中的是哪一个人 / 物体 | **分割**：人像实例、物体分割 |
| 点中的主体本身前后有深度差 | **例外**：点中的那一个主体整体拉到对焦面，和系统相机一致（唯一不按深度来的地方） |

两种过渡的分工：

- **沿深度方向的过渡**（斜着往远处延伸的桌面）：镜头曲线本身是连续的，只要中间不整片改写深度，就不会出现硬过渡。
- **画面上主体和背景交界的过渡**（头发和后面的墙）：深度图在这里是糊的，靠分割和颜色把边界修准。

## 3. 每帧总流程

```
 相机帧 + 深度帧（同步输出）              Vision 分割（单独队列，取最近一次结果）
          │                                         │
          ▼                                         ▼
 CameraController ──裁切、颜色小图──►  LiveFrameAnalyzer.analyze        CPU，深度图分辨率（≤ 320×240），几毫秒
                                              │  输出 FramePlan
                                              ▼
                                     MetalBokehRenderer.encode          GPU，低分辨率（≈ 输出长边 / 3）+ 全分辨率合成
                                              │
                                              ▼
                                     MetalPreviewView（有新帧才画）
```

`FramePlan` 里有：

- 镜头参数 `lens`（已按焦距换算）
- 对焦点、对焦视差、对焦距离
- 补好洞、修过边的深度图 `depth`
- 主体种子 `seeds`：`connect` / `extra` / `person` 三张小图（见 §5.7）
- 分层位置 `layerCenters`
- 运动信息：`stillness`、`cameraShift`、`depthAge`
- 遮罩是否过期：`personMaskStale` / `objectMaskStale`，决定下一帧分割跑多勤

GPU 跟不上（已有 2 帧没算完）时，丢掉新帧，不排队。

## 4. 第 0 层：深度从哪来

| 倍率 | 实际用的相机 | 深度 | 单位 | 系统深度滤波 |
|---|---|---|---|---|
| 0.5×–0.99× | 超广角 | AI 单目（Depth Anything V2） | 每帧归一化，不是 1/米 | — |
| 1×–1.99× | 主摄 + LiDAR | LiDAR | 1/米（绝对） | 开 |
| 2×–3.99× | 双摄广角（主摄原生 2×） | 双摄视差 | 相对值，带 +0.2～0.4 偏移，约等于真实值 | 开（还没录对比数据） |
| 4× | 双摄长焦 | 双摄视差 | 相对值，**只有真实值的约 1/4** | **关**（`usesSystemDepthFilter`） |
| 前置 | TrueDepth，不行时退回 AI | | | 开 |

- **两个倍率点之间**：相机停在低的那个点，画面和深度图一起从中间裁。路线规划在 `LensCatalog`。
- **4× 不用系统滤波**：系统滤波在长焦下会把白墙、屏幕上的洞补成偏近的值。关掉后洞由 `DepthRefiner.fillInvalid(_:guide:)` 按这一帧的颜色补。
- **没有新深度的帧**（`depthAge ≥ 1`）：不用旧深度，而是在 GPU 上把上一帧对齐好的深度按画面运动搬过来（`StaleDepth`，`stale*Kernel`）。

## 5. 第 1 层：CPU 分析 `LiveFrameAnalyzer.analyze`

只处理深度图分辨率的数据。拍照用同样规则的 `stillPlan`（§8）。

### 5.1 补洞

`DepthRefiner.fillInvalid(depth.centerCropped(by: crop), guide: colors)`：pull-push，按颜色引导，主要从同色的有效像素补。

### 5.2 对焦

- 对焦点被裁出画面时回到中心。
- `FocusStabilizer.update`：
  - 取对焦点 3% 窗口的中位数。
  - 变远时最多坚持 1.5 秒（主体滑出对焦点）。
  - 变近时只坚持 0.3 秒。
  - 扫镜头时也只坚持 0.3 秒。
  - 时间常数 0.12 秒平滑拉焦。
- 锁定对焦（`focusLocked`）：点按后先照常测 0.4 秒（`lockSettleTime`），然后锁住目标距离，不再测。换相机后重新测一次再锁。
- 注意：对焦是在 §5.7 修边**之前**测的。

### 5.3 主体太近

只对 LiDAR 生效：主体近于 0.30 m 时，景深在 0.15 秒内淡出（进出留 12% 回差）。

### 5.4 镜头 `LensParameters`（`.system` 模型）

```
Δd = d − d_f                                    （1/米；> 0 前景，< 0 背景）
背景  g = 0.95 · tanh(1.6 · max(|Δd| − 0.04, 0) / 0.95)
前景  g = 1.2  · tanh(1.6 · max( Δd − 0.25, 0) / 1.2)
r = g · blurK / ƒ · 长边                        blurK = 0.016，上限 1.4% 长边
```

- **按焦距换算**（`scaleForFocalLength`），只在焦距 > 24mm 时生效：
  - 斜率 × s，`s = (焦距 / 24)^1.35`（`focalScalingExponent`）。真实镜头是 2，1.35 是对着系统相机录屏调的；
  - 后面的全清晰区 ÷ s；
  - 前面的全清晰区 ÷ (焦距 / 24)²（`toleranceScalingExponent`，景深和焦距的平方成反比），最窄到 0.04（`minScaledFrontTolerance`，再窄就和长焦双摄视差的误差一个量级）。
    2× 是 0.0625，3× 起是 0.04。以前和斜率共用 1.35，2× 是 0.098：对焦远处的墙时，5–7 m 的东西完全不糊（录屏 demo1030 / xitong1030）。
- **`sharpDisparityRange(limit:)`**：反算出「虚化 ≤ 长边 limit」的视差区间。主体遮罩里所有「按镜头本来就清晰」的判断都用它。
- **`relativeScale`**：只给主体遮罩的 ±25% 判断当分母，不影响虚化量。只有相对深度才有：`max(d_f, 0.25 × (近端 − 远端))`，近端、远端取 5% / 95% 分位，跨帧平滑。

### 5.5 分层位置

按这一帧深度的最近、最远算出带符号的模糊半径范围，切成层（预览每侧 5 层，拍照每侧 9 层），靠近对焦面切得更密。

### 5.6 运动估计

和上一帧小图比亮度，得到：

- 整体平移 `cameraShift`
- 静止程度 `stillness`
- 变化像素比例 `changedFraction`

平移 ≥ 2 像素算扫镜头（延续 0.25 秒）。

### 5.7 主体部分

只在 `keepSubjectSharp` 时做。

1. **遮罩对齐到这一帧**（`alignMask`）。分割是几帧之前算的，所以：
   - 先在长边约 80 的小图上估计整体平移，遮罩跟着挪过来；
   - 画面变了的地方不再相信遮罩；
   - 遮罩那块变了 ≥ 2% 时，标记为过期，下一帧重新分割。
2. **按人像遮罩修深度边缘**（`SegmentEdgeRepair.repair`）：
   - 人像遮罩里所有人按连通块分开；
   - 分界线两侧各 `edgeRepair` 宽（深度图长边的 1/80：160 宽时 2 像素，320 宽时 4 像素）的深度当作不可信；
   - 不可信的像素从**同一侧**最近的可信像素一圈圈往里填：头发、眼镜拿到人的深度，外面一圈光晕拿到背景的深度；
   - 两块人像直接挨着时，人和人之间的交界不修；
   - 遮罩过期的地方不修。

   这一步改的是 `depth`，之后所有步骤都用修过的深度。
3. **只留点中的那一个人**：
   - **有人像实例时**：用 `focusedInstance` 找点中的人。判断条件是对焦点上的实例，并且他在对焦点附近（4% 窗口）的深度中位数按镜头算虚化 ≤ 0.3%。
     - 其他所有实例从人像遮罩里移除（`otherInstances`，不看深度）；
     - 再去掉点中这个人外扩 1/30 以外的部分，挨着他、但 Vision 没编号的第 5 个人不会跟着清晰。
   - **没有实例，或点中的是没编号的人**（`depthRestricted`）：只留人像遮罩里按镜头算虚化 ≤ 0.3% 的部分，先腐蚀 1 像素当种子，再外扩约 1/30。
4. **点中的物体**（`addObject` / `refineObject`）：
   - 物体分割里对焦点所在的那个物体，像素中有 ≥ 60% 在对焦面 ±25% 以内才用。
   - 物体里深度对不上的部分，以下情况仍算物体：
     - 贴着主体的细条（宽度不超过深度图长边的 1/40）；
     - 成块但深度和旁边背景一样（说明是背景深度渗进来了）。
   - 成块、有自己深度的部分（比如后面的罐子）去掉。
   - 处理后的物体并进人像遮罩。
5. **生成种子**（`SubjectMatte.seeds`）：
   - **`connect`（深度核心）**：
     - 范围 = 镜头清晰范围（虚化 ≤ 0.15%，`sharpLimit`）∩ 对焦面 ±25% ∩ 和对焦点连通（在对焦点附近 8% 范围内找起点）。
     - 不膨胀。
     - 对焦点附近一个镜头清晰的像素都没有时，退回只用 ±25%。
   - **`extra`（不看深度直接算主体的像素）**：
     - `growByColor` 颜色补边：核心外 D 以内（相对深度时 D = 长边的 1/24，LiDAR 时 1/40）、不在对焦面前方 25% 以外、颜色明显更像主体（和附近主体颜色的距离平方不到和背景颜色的 1/4）、并且和核心连着的像素；
     - 加上 `person > 0.5` 的像素。
   - **`person`（软边遮罩）**：
     - 点中的那个人或物体（`personRegion`：和对焦点连着的那块），
     - 取最大值合并 `sharpPeople`：所有人身上按镜头本来就清晰（≤ 0.15%）的像素，锁在对焦面，防止细眼镜框在渲染时再被抹糊。

## 6. 第 2 层：GPU 渲染 `MetalBokehRenderer.encode`

着色器和 CPU 版（`DetailPreserving` / `SubjectMatte.apply` / `BokehRenderer`）公式一样。

1. **缩小**：相机帧缩到低分辨率（长边 ≈ 输出 / 3，至少 160），并算出亮度。
2. **深度对齐**：上采样，再做灰度引导滤波，让深度边缘贴住画面轮廓。没有新深度的帧走 `stale*` 搬深度。
3. **跨帧稳定**：画面没变的地方，深度向上一帧靠（`temporalDepthKernel`）。新深度来的那一帧，之前搬过的区域不沿用。
4. **主体遮罩**（`subjectCore` → `gf*Color` → `subjectFix`）：
   ```
   深度核心 = |d − d_f| / norm < 0.25  且  connect ≥ 0.5
   核心     = 深度核心 或 extra ≥ 0.5
   α        = max( smoothstep(0.25, 0.75, 彩色引导滤波(核心)),  smoothstep(0.3, 0.7, person) )
   d'       = d + α · (d_f − d)                                  ← 拉到对焦面
   leak     = max(0, 深度核心 − α)                               ← 颜色说「不是主体」
   若 leak > 0 且附近最远视差 < d_f − 0.25·norm：d' 向附近最远视差推（按背景虚化）
   ```
   彩色引导滤波的半径为长边的 1/70。
5. **算模糊半径、高光**：每个像素按 `d'` 算带符号的模糊半径，再做高光提亮（形成光斑）。
6. **分层圆盘模糊**：
   - 背景层从远到近 over 合成；
   - 被遮挡的洞用 pull-push 外推补上；
   - 前景层加法累积后整体盖上去；
   - 大半径的层先降采样再模糊。
7. **虚化程度 w 和焦外稳定**：`w = max(smoothstep(0.25, 0.9, 自身半径), smoothstep(0.015, 0.06, 和原图的差))`，焦外区域再做跨帧平滑。
8. **合成到全分辨率**：`输出 = 放大(虚化结果) + (1 − w) · (全分辨率原图 − 放大(低分辨率原图))`，清晰的地方保留原图细节。

## 7. 在算虚化之前，一个像素的视差可能被谁改写

这张表是排查「为什么这里清晰 / 不清晰」的入口。

| # | 入口 | 代码 | 改成什么 | 依据 |
|---|---|---|---|---|
| 1 | 补洞 | `DepthRefiner.fillInvalid(guide:)` | 无效像素 ← 同色有效像素 | 颜色 |
| 2 | 按分割修边 | `SegmentEdgeRepair.repair` | 人像分界两侧 ← 同侧最近的可信深度 | 分割（所有人） |
| 3 | 引导滤波上采样 | `upsampleDepth` + `gf*Gray` | 深度边缘贴颜色边缘 | 颜色 |
| 4 | 跨帧 / 搬旧深度 | `TemporalState`、`StaleDepth` | 向上一帧靠 / 按运动搬 | 时间 |
| 5 | 深度核心 | `connect` → `subjectCore` | 拉到 d_f | **镜头**（≤ 0.15%）∩ ±25% ∩ 连通 |
| 6 | 颜色补边 | `growByColor` → `extra` | 拉到 d_f | 颜色（核心外 D 以内；对后方深度不设限） |
| 7 | 引导滤波软边 | `gf*Color` 的 α | 核心外约 1/70 以内部分拉向 d_f | 颜色 |
| 8 | 点中的人 | `person` | 拉到 d_f | **身份**（实例）+ 对焦点附近 ≤ 0.3% |
| 9 | 点中的物体 | `addObject` → `person` | 拉到 d_f | **身份** + ±25% 一致率 60% |
| 10 | 别人本来清晰的像素 | `sharpPeople` → `person` | 拉到 d_f（原本就 ≤ 0.15%） | 镜头 |
| 11 | 没实例时的外圈 | `depthRestricted` | 清晰部分外扩约 1/30 | 分割 |
| 12 | leak | `subjectFix` | 核心里 α 低的 → 附近最远视差 | 颜色 |

- **1–4 是「修深度」**。
- **5–12 是主体遮罩**，最终都表现为把视差拉到对焦面，或者推远。
  - 严格按镜头的是 5 和 10。
  - 8、9 是「点中主体整体清晰」这个例外。
  - 6、7、11、12 是边缘规则，按颜色或分割，不按镜头。

## 8. 「算不算同一个深度」的阈值一览

| 阈值 | 值 | 用在 |
|---|---|---|
| 镜头全清晰区 | 前 0.25 / 后 0.04（1/米）；长焦时前面 ÷ (焦距/24)²、最窄 0.04，后面 ÷ s | 虚化量本身 |
| `sharpLimit` | 长边的 0.15% | 深度核心、`sharpPeople` |
| 2 × `sharpLimit` | 长边的 0.3% | `focusedInstance`、`depthRestricted` |
| `band` | 对焦面 ±25%（分母 `relativeScale`） | 深度核心的外框、颜色补边的前方上限、物体一致率、`refineObject`、leak 的判断 |
| `objectDepthAgreement` | 60% | 物体整体清晰的门槛 |
| `FocusStabilizer.relativeTolerance` | ±15% | 对焦稳定 |

`band`（±25%）是 1× 时定的，长焦下比镜头清晰范围宽得多：

- **深度核心**：已经被镜头范围收窄，不受影响。
- **物体一致率、颜色补边、leak**：仍按 ±25% 判断。

## 9. 分割：跑什么、用来做什么

| 分割 | Vision 请求 | 用来做什么 |
|---|---|---|
| 人像遮罩（所有人一张图） | `VNGeneratePersonSegmentationRequest` | ① 给所有人修深度边缘（§5.7-2）；② `sharpPeople`；③ 点中的人的软边 |
| 人像实例（每人一个编号，最多 4 人） | `VNGeneratePersonInstanceMaskRequest` | 只用来认出「点中的是哪一个人」 |
| 物体（前景实例，512×512 标签图） | `VNGenerateForegroundInstanceMaskRequest` | 点中的物体整体清晰（**不用来修边**） |

- **以前**：分割决定谁清晰。
- **现在**：分割只负责「边界在哪」和「点的是哪一个」。
- **跑多勤**：看点中的是不是人、在不在动、画面在不在动（`PersonSegmenter.update`，频率表见 README）。
- **方向**：结果要从 Vision 的竖拍方向转回传感器方向（`VisionOrientation`）。

## 10. 拍照与拍后编辑

- **`LiveFrameAnalyzer.stillPlan`**：规则和预览一样。区别：
  - 没有跨帧历史；
  - 对焦直接取 3% 窗口中位数，锁定对焦时用锁定的距离；
  - 低分辨率长边至少 320；
  - 用 `RenderQuality.photo`（每侧 9 层）。
- **`PhotoBokehEditor`**：
  - 改 ƒ 值、换对焦点后整张重新渲染；
  - 走同一套 Metal 着色器，GPU 不可用时退回 CPU；
  - 拖动滑块时只渲染最新一组参数。

## 12. 验收和调试

- **`ScenarioMatrixTests`**（`swift test -c release --filter ScenarioMatrixTests`，加 `NOISE=0.04` 把深度噪声放大 10 倍）：
  - 规模：13 个合成场景，人、物体、桌面、多人、眼镜光晕、长焦白墙、2× 对焦远墙都有；配 7 种深度来源和焦段，有 / 无人像实例各跑一遍，共 168 个组合。
  - 走的处理流程和 App 一样（`LivePreviewPipeline`）。
  - 判定规则（虚化半径按长边的 %）：
    - 主体中位数 > 0.15% →「主体糊了」；
    - 主体和后面东西交界的一圈，80% 分位 > 0.3% →「主体边缘糊」；
    - 其他区域：理想 ≥ 0.4% 但实际不到一半 →「该糊没糊」；理想 < 0.1% 但实际 > 0.35% →「不该糊糊了」；
    - 有过渡区域的场景（目前只有「桌面」）：跨一个深度像素的跳变比理想多 0.2% 以上 →「硬过渡」。
  - 「理想值」把点中主体当成整体清晰来算，所以已经包含了 §1 的例外。
- **`MetalParityTests`**：在 Mac 上逐步对比 GPU 和 CPU 的结果。
- **`bokeh-cli --live`**：用手机录的数据（整帧 jpg + 深度 pfm + `frames.jsonl`）跑同一份代码，逐帧对照。

## 13. 和「三步计划」的对照

计划：先把虚化做成只看镜头 → 再用分割修边 → 最后决定点中主体是否整体清晰。

| 步骤 | 计划 | 现状 | 偏差 |
|---|---|---|---|
| 1 虚化只看镜头 | 去掉按身份判断清晰；整片填充改成镜头清晰范围 | 已做：深度核心改用 `sharpLimit`；删掉 `otherPeople` 等按身份留人的补丁 | 找不到镜头清晰像素时退回 ±25%；颜色补边、软边、leak 仍不是镜头标准（§7 #6 #7 #12） |
| 2 分割只修边 | 每个人或物体用自己的深度修边；没被分割的靠颜色补边 | 人：已做（`SegmentEdgeRepair`） | 物体没修边；修边按人像连通块，不按实例；颜色补边对所有主体都跑，不只是没被分割的 |
| 3 主体整体清晰 | 待定 | 实现时按建议定为「整体清晰」（人和物体都是），对话里没有单独确认 | 物体是否启用仍按 ±25% / 60% 判断 |

## 14. 已知问题和待定事项

- **4× 视差单位**：长焦当主镜头时，双摄视差只有真实值的约 1/4，所以 4× 实际比 2×–3.9× 虚化弱。暗光或很近时系统会换回主摄裁切，虚化会突然变强。乘回 4 倍会放大深度噪声，需要配一层去噪，暂时没做。
- **0.5× AI 深度**每帧归一化，不是真实距离，所以虚化量不是物理意义上的。
- **2× 系统滤波**是否也会补错，还没有对比录制。
- **Vision 人像实例最多 4 人**：超出的人照样按深度虚化，但只能走 `depthRestricted` 这条更粗的路。
- **对焦在修边之前测**：点在头发、眼镜边上时，对焦面可能取到背景深度（3% 窗口中位数通常能扛住）。
- **场景矩阵的判定较松**：中间段（理想 0.1%–0.4%）和「糊过头」不报错；过渡检查只覆盖桌面一个场景。
- **`focalScalingExponent` = 1.35**：凭观感调的，真实镜头是 2。全清晰区已经按 2 换算（2× 有系统相机录屏对照）；斜率没动。
- **2× 后面的虚化可能偏强**：同一段录屏里对焦 4.5 m 时，14 m 的墙系统相机约 0.22%，demo 约 0.55%（ƒ1.4）。只有这一组数据，没改。
- **1× 对焦远处时前面同样不糊**：前面 0.25 的全清晰区在 1× 对焦 14 m 时一直延伸到 3.1 m。1× 没有系统相机对照录屏，没改。
- **加大深度噪声（`NOISE=0.04`）时，「长焦桌面 / 对焦柜子 / 100mm」2 个组合主体边缘糊**：改全清晰区之前就是这样。
- **合成场景的边缘都是干净色块**：真实的头发、眼镜、快速移动只能在真机上看。

## 15. 改代码时的约定

- **CPU 和 GPU 一起改**：`BokehShaderSource` 照抄 CPU 的公式、半径、边界处理和求和顺序。改完在 Mac 上跑 `swift test`，里面包含 `MetalParityTests`。
- **改镜头、主体遮罩或分析之后**：在 Release 下跑一遍场景矩阵，再加 `NOISE=0.04` 跑一遍。
- **遇到新的问题场景**：照着 `ScenarioMatrixTests` 里的 `Scene` 加一个，放进 `cases`。
- **`BokehCamera` / `App` 依赖 UIKit 和 AVFoundation**：只能在 Xcode 里编译、真机验证。
